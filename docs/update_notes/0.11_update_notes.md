# 0.11 版本更新日志

> 发布版本：`0.11.0`
>
> 发布日期：2026-07-16
>
> 变更范围：`0.10.0` 至 `0.11.0`

## 版本概览

0.11 以“可靠运行、可控执行、可持续维护”为主线，对 MQTT、自动化、历史查询、在线状态、平台配置和部署链路进行了系统性加固。业务 MQTT 长连接现在由唯一 runner 持有，Web worker 通过 Redis Streams 发送命令；自由 Python 自动化默认关闭，并改为独立限时进程执行；历史接口增加边界和索引，数据时间统一采用服务端接收时间判断。

本版本也收录 0.10 之后已进入主线的资源文件夹、P&ID 编辑能力、MCP 服务、批量删除和新硬件支持。

主要亮点：

- MQTT 单 runner、持久会话、PUBACK、pending 恢复、租约和健康检查
- 自动化脚本默认关闭，仅超级管理员可用，独立进程强制超时
- 历史查询消除 N+1，增加窗口与数量限制以及最新值复合索引
- 数据与心跳原子写入，以服务端时间维护单调在线状态
- 平台配置和 MQTT 密码全链路脱敏，生产密钥缺失时拒绝启动
- Redis AOF、可选维护模式数据清理、依赖锁定和 GitHub Actions 持续集成
- 资源文件夹、P&ID 绑定校验、标准 MCP 服务和新硬件节点
- 177 项后端测试全部通过

## 一、安全基线与配置保护

### 生产配置

- `DEBUG=False` 时必须通过环境变量提供 `SECRET_KEY`，缺失时服务拒绝启动。
- 健康检查仅返回必要状态，不向客户端暴露数据库异常、凭据或内部实现信息。
- 平台配置键创建后不可修改，API、命令行和 Django Admin 共用统一类型与取值校验。
- `mqtt_password` 在普通 API、超级管理员 API 和 Django Admin 中均不回显；提交掩码值时保留原密码。
- WebSocket 鉴权读取 JWT 后会立即从 ASGI scope 移除 `token` 参数；Nginx 的 `/ws/` access log 只记录不含查询参数的路径，避免 token 进入应用与容器日志。

### 自动化权限

- 自动化规则创建、修改、删除、手动执行统一收紧为超级管理员权限。
- 自由 Python 脚本默认关闭，必须显式设置 `AUTOMATION_SCRIPT_EXECUTION_ENABLED=True` 才能启用。
- 未启用脚本能力时，API 明确返回不可用状态，Admin 和调度器也不会绕过限制。

## 二、MQTT 单进程与命令可靠性

### 单一连接所有者

- ASGI Web worker 不再持有用于业务收发的常驻 Paho MQTT client；超级管理员连接测试仍使用短生命周期临时 client。
- 所有控制命令写入 Redis Streams，由独立 `iot-mqtt-runner` 统一发布。
- runner 使用稳定 client id 和持久会话，重连期间可由 broker 保留 QoS 1 消息。
- Redis 租约保证同一部署中只有一个有效 runner；租约和工作线程状态同时进入健康检查。

### 命令投递

- 发布后等待 broker PUBACK，并分别限制 broker 确认与设备确认时间。
- runner 重启后先等待 broker 连接，再恢复 Redis consumer group 中的 pending 命令。
- runner 停止时可中断设备确认等待，未完成命令保留在 pending，不会被误删。
- API、自动化和 worker 端均重新校验命令名、参数和超时时间，防止异常请求长期占用工作线程。

### 上报与死信

- 上报成功落库后才通过 Paho manual ack 确认 MQTT QoS 1 消息。
- 处理失败时写入有界死信队列后确认；死信写入失败则保留 pending，避免静默丢失。
- 入站 payload、死信 payload 和死信队列长度均设上限，降低毒消息导致内存耗尽的风险。
- MQTT 配置支持运行期刷新，不再依赖重启所有 Web worker。

## 三、自动化执行隔离

- 自由脚本通过 `spawn` 创建独立子进程，不在 API 或调度器主进程内直接执行。
- 单次执行默认最长 10 秒、硬上限 60 秒；超时后依次终止并强制清理整个进程组。
- stdout、日志、结果协议文件均限制大小，临时目录和文件使用收紧后的权限。
- API、Django Admin 和 scheduler 共享同一执行器与 Redis 单飞锁，同一规则不能并发运行。
- Redis 不可用时执行器 fail closed，避免多个 worker 同时运行同一脚本。
- scheduler 仅由 `iot-mqtt-runner` 启动，防止多 ASGI worker 重复调度。

> 独立进程用于超时和故障隔离，并不是操作系统安全沙箱。自由脚本仍只能开放给完全可信的超级管理员。

## 四、查询性能与 API 边界

### 历史查询

- Sensor、Device 列表移除历史数据整表预取，改为相关子查询和聚合。
- Project snapshot、series、bindable sources 和 dashboard 消除多处 N+1 查询。
- Project 与 `data_viz` 严格校验 ISO 起止时间，Sensor 与 Device 严格校验 `hours`；各历史接口均限制时间窗口和最大 `limit`。
- 结果使用 `(timestamp, pk)` 稳定排序，避免同一时间戳分页或截断结果不确定。
- Project series 只允许查询当前项目已经绑定的数据源。

### 数据库优化

- SensorData 新增 `(sensor, -received_at)` 复合索引。
- SensorStatusCollection 新增 `(sensor, -received_at)` 复合索引。
- DeviceStatusCollection 新增 `(device, -received_at)` 复合索引。
- MySQL 开启短时连接复用与使用前健康检查，减少频繁握手并自动替换失效连接。

## 五、时间戳、在线状态与事务正确性

- 最新状态与在线心跳统一以服务端 `received_at` 为可信依据，不再使用设备上报的未来时间判断在线。
- SensorData、SensorStatusCollection、DeviceStatusCollection 与父对象心跳在同一事务中写入。
- 实时 WebSocket 广播统一在事务提交后执行，客户端不会提前看到尚未提交的数据。
- 使用数据库 `Now()` 和单调更新避免并发请求让 `last_seen` 倒退。
- 未来 `last_seen` 在模型、序列化器、查询过滤和 dashboard 中统一视为离线。
- 数据迁移会清理历史上明显超前的 `last_seen`，并重置对应在线状态。
- Sensor/Device ID 重命名不再覆盖用户自定义 MQTT topic。
- Sensor 与 Device 命令入口统一拒绝空命令名和非法参数。

## 六、资源管理、P&ID 与实时通道

### 资源文件夹与批量操作

- 新增 Sensor、Device、AutomationRule 资源文件夹及分页接口。
- 支持递归文件夹名称、Admin 过滤和前端文件夹浏览。
- Sensor 与 Device 列表新增批量删除能力。

### P&ID 与结构化控制

- ControlScheme 状态接入实时通道，项目工作台可以增量更新控制状态。
- 新增控制指示器、设备指示器和专用 P&ID 边类型。
- 画布保存时校验节点、边和绑定结构，拒绝损坏或越权的数据源绑定。
- 节点尺寸序列化与对齐逻辑统一，编辑器和运行时采用相同几何信息。

### WebSocket 与插件

- 动态 WebSocket group 名称进行安全化和稳定哈希，生产者与消费者采用同一规则。
- WebSocket 的 `token` 参数在鉴权后立即清除，Nginx 为 `/ws/` 使用无查询参数日志格式，握手成功和拒绝日志均不再记录 JWT。
- 插件 manifest 严格校验名称和布尔字段。
- 仅在插件登记表尚未创建时允许使用 manifest 回退；数据库异常时 fail closed。
- `data_viz` 同步采用严格时间窗口、ISO 时间和数量限制。

## 七、MCP 与硬件扩展

### MCP 服务

- 新增标准 MCP 子项目、容器服务、API client、控制确认机制和完整测试。
- 支持 AI Agent 查询传感器、设备和平台资源，并对控制类操作保留确认边界。
- 原实验性 OpenClaw 目录由结构清晰、可独立部署的 MCP 服务替代。

### 硬件

- 新增 ESP32 HC-SR04 超声波/液位采集与 MQTT 数据、状态、命令格式。
- 新增 Wemos D1 MG90S 舵机控制与状态上报示例。
- Sensor 增加独立 MQTT status topic 支持，命令发送接口和文档同步统一。

## 八、部署、清理与持续集成

- Redis 开启 AOF `everysec`，将主机故障时的持久化丢失窗口控制在约 1 秒。
- 新增可选 `maintenance` profile 的 `data_cleanup` 服务，分批清理传感器采样、传感器状态和设备状态历史数据；常规 `docker compose up -d` 默认不启动。
- 维护容器每次启动先执行 dry-run，默认等待 24 小时后才首次真实清理；清理 API 默认预览，真实删除必须提交明确确认短语。
- 数据保留天数和清理批次均进行严格范围校验。
- Python 运行依赖改为精确版本，Dockerfile 移除重复安装步骤。
- 新增 GitHub Actions 后端流水线，使用 MySQL 8 与 Redis 7 执行依赖、Django、迁移和完整测试检查。
- `mqtt_runner` 增加 Compose 健康检查，backend、runner 和清理服务启动依赖关系更加明确。

## 九、不兼容变化与升级提示

### Redis 成为控制命令硬依赖

Web worker 不再回退为进程内 MQTT 直连。Redis 不可用时控制命令会明确失败，以避免多 worker 重复发布或返回虚假成功。

### 自动化脚本默认关闭

升级后自由 Python 自动化不会自动运行。如确需使用，必须由可信运维人员在 `.env` 中显式配置：

```dotenv
AUTOMATION_SCRIPT_EXECUTION_ENABLED=True
AUTOMATION_SCRIPT_TIMEOUT_SECONDS=10
AUTOMATION_SCRIPT_LOCK_PREFIX=spr:iot:automation:execution
```

### 新增迁移

本版本必须包含并执行：

- `automation`：`0001` 至 `0006` 完整迁移链
- `sensors`：`0009` 最新数据索引与未来心跳清理
- `devices`：`0014` 最新状态索引与未来心跳清理

`automation/migrations/` 过去曾被 `.gitignore` 错误排除，本版本已修正并将完整迁移链纳入仓库。

### 新增或重要环境变量

| 变量 | 默认值 | 作用 |
|------|--------|------|
| `AUTOMATION_SCRIPT_EXECUTION_ENABLED` | `False` | 是否允许自由 Python 自动化 |
| `AUTOMATION_SCRIPT_TIMEOUT_SECONDS` | `10` | 单次脚本硬超时，最大 60 秒 |
| `AUTOMATION_SCRIPT_LOCK_PREFIX` | `spr:iot:automation:execution` | 自动化分布式锁前缀 |
| `MQTT_INBOUND_MAX_PAYLOAD_BYTES` | `262144` | MQTT 入站消息上限 |
| `MQTT_DEAD_LETTER_MAX_PAYLOAD_BYTES` | `65536` | 单条死信保存上限 |
| `MQTT_COMMAND_BROKER_ACK_TIMEOUT` | `2` | broker PUBACK 等待秒数 |
| `DB_CONN_MAX_AGE` | `60` | MySQL 连接复用秒数 |

生产环境还应确认 `DEBUG=False`、强随机 `SECRET_KEY`、准确的 `ALLOWED_HOSTS`、CSRF 来源和安全 Cookie 配置。

## 十、Docker 升级步骤

升级前请先备份 MySQL 数据库或数据卷，并保留当前 `.env` 的安全副本。

```bash
git fetch --tags
git checkout 0.11.0
docker compose up -d --build
```

backend 启动时会自动执行迁移。上述常规启动不会创建 `data_cleanup`。启动完成后检查：

```bash
docker exec iot-backend python manage.py showmigrations automation sensors devices
docker ps
docker logs iot-backend --tail 50
docker logs iot-mqtt-runner --tail 50
```

确认 `iot-backend`、`iot-mqtt-runner`、`iot-redis` 和 `iot-mysql` 均正常运行后，再进行设备控制验证。

如需周期清理，先预览并核对预计删除量：

```bash
docker compose exec -T backend python manage.py cleanup_old_data --dry-run
docker compose --profile maintenance up -d data_cleanup
docker logs iot-data-cleanup --tail 50
```

维护容器会再次 dry-run，并在默认 24 小时安全延迟后才进行第一次真实清理。也可以通过超级用户 API 预览；真实删除必须提交 `{"dry_run": false, "confirmation": "DELETE_EXPIRED_HISTORY"}`。

## 十三、已知边界

- MQTT QoS 1 是“至少一次”语义；数据库提交后、消息确认前的极端崩溃窗口仍可能造成重复上报，业务处理必须保持幂等。
- 控制命令获得 broker PUBACK 后若设备结果未知，不会自动重试，以避免执行器重复动作。
- 死信当前用于有界留存和人工排查，尚未提供自动 replay 工具。
- Redis AOF `everysec` 在宿主机故障时仍存在约 1 秒数据窗口。
- 自动化独立进程不是 OS 安全沙箱，只能向可信超级管理员开放。
